Click the picture and type: the PC keyboard is mapped by key position to the MSX international layout. F1–F5 are the function keys, F8 (or End) is STOP, F7 is SELECT, left Alt is GRAPH and right Alt is CODE; CTRL+STOP breaks into a running BASIC program. On the keyboard above, SHIFT, CTRL, GRAPH and CODE stay down for the next key. Load ROM takes the 32 KB BIOS (hb-55p_basicbios1.rom) and, if you want Sony's built-in Personal Data Bank, the 16 KB firmware (hb-55p_firmware.rom); you can pick both files at once. Untick Built-in software to start in MSX BASIC. Cartridge ROMs go in slot 1; plain ROMs and the four common mega-ROM mappers are supported. Listing gives the system variables, the BASIC program as text, the screen and hex dumps. Cassette: insert a .cas tape file and type the command shown (CLOAD for BASIC programs, BLOAD"CAS:",R for machine code, RUN"CAS:" for ASCII files); loading is instant and the tape moves on to the next file each time. CSAVE, BSAVE and SAVE"CAS:" record to a new tape that Save recording downloads as a .cas file. Many tape programs need more than 16K: choose the HB-75P for those. Sound plays while the machine runs in real time (it starts with your first click or key press, as browsers require); the sound chip's registers are also shown in the MSX hardware panel. The ROMs are not included; your browser keeps the BIOS and firmware once loaded.

Memory chips live pins · click a pin to disconnect it or hold it high or low

The machine's memory chips, from the Sony service manual's schematic: the system ROM (IC42 BIOS and IC43 BASIC) and the firmware ROM (IC44); the main RAM, IC58–IC61 and IC65–IC68, one chip per data bit (4116s in the HB-55P, 64K chips in the HB-75P); and the eight 4116s of the video RAM (IC3–IC6 and IC9–IC12). A tile's dot lights while its chip is being accessed. Click a tile to see that chip's pins, which follow the bus on every clock. The video RAM belongs to the video processor: its pins are shown for the CPU's reads and writes through port 98h, not for the picture being drawn. Cartridges are not included.

To simulate a fault, click a pin: Disconnected lifts the pin from the board (an input then floats high, an output no longer reaches the bus), Stuck high and Stuck low hold it at that level. An address pin fault makes the chip use the wrong cell; a data pin fault changes that bit on reads and writes; chip select held high (or a fault on RAS or CAS of a dynamic RAM) takes the chip out of circuit; write enable held high loses writes, held low turns every access into a write. Faults are listed in the Debug panel and cleared there, here, or by Master reset. The memory view and the disassembly show what the CPU reads through the faults.

Clicking CLK pulses one clock. /INT is level-sensitive, /NMI triggers on a falling edge. Holding /WAIT low inserts wait states; /BUSREQ low floats the buses at the end of the current machine cycle; /RESET low holds the CPU in reset.

Program

Standard Zilog syntax, one instruction per line. Labels end with :; comments start with ;. Directives: ORG, EQU, DB, DW, DS, END. Numbers: 1Fh, 0x1F, $1F, %1010, 'A', and $ for the current address. Undocumented instructions (IXH, SLL, OUT (C),0) are accepted. Code starts at the Load at address; an ORG in the source overrides it. Import a file with the button or by dropping it on the editor.

Hex bytes separated by spaces or newlines. Text after ; is ignored. Write 0100: to continue loading at another address. Memory

Scroll through all 64 KB as the CPU sees it now, through whichever slots are switched in. Click a byte to edit it (RAM only). Blue marks the instruction being executed, amber marks bytes written by the last instruction, underline marks the top of the stack. With Follow PC ticked, each step brings the current instruction back into view; untick it to keep watching another area.

Memory bitmap

Point at the bitmap to read a byte; click to show it in Memory.

Every bit of memory is one pixel. Each byte is a row of 8 pixels (bit 7 on the left) and each strip is one 256-byte page, read top to bottom; each band holds 8K. The background colour shows what each part is being used for: in RAM, read from BASIC's own system variables; in video RAM, from the video processor's table registers, so you can see the screen (name table), the character shapes and the sprites, and watch them move when a program changes screen mode. The red mark is the program counter and the blue mark the stack pointer, shown on the bands whose slot is switched in.

    MSX hardware slots · video · PPI · sound

    Each 16K page of memory shows one of four slots, chosen by two bits of PPI port A (port A8h). The video processor has its own 16K of video RAM, reached only through ports 98h (data) and 99h (address, registers, status); it raises the machine's one interrupt at the end of every picture, 50 times a second. PPI port C (AAh) picks the keyboard row that port A9h reads. The sound generator sits on ports A0h–A2h.
