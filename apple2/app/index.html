Click the picture and type. Your keyboard's letters, digits and symbols go in as the Apple II Plus encoder sends them: upper case only, so lower case letters are typed as capitals. Enter is RETURN, Backspace and the left arrow are ←, the right arrow is →, Esc is ESC, and Ctrl with a letter gives the control code. The keys drawn above are the II Plus keyboard: CTRL and SHIFT stay down for the next key, and RESET works with CTRL, as the keyboard's switch is normally set (so it resets the machine only after CTRL). Holding a key does not repeat it unless REPT is down, as on the real keyboard. Load ROM folder asks for the folder that holds your ROM files and recognises the Apple II Plus ROMs by their contents; the row of sockets shows which file sits in each socket on the board, and clicking a socket fits a ROM of your own there instead. Type it sends text through the keyboard, so BASIC programs and Monitor commands can be pasted in. Load binary file puts a file into RAM at the address given (start it from BASIC with CALL and the address in decimal, or from the Monitor with the address and G). The cassette plays a recording of an Apple tape into the cassette input (C060h): type LOAD in BASIC, or the address range and R in the Monitor, then press Play; Tape from binary makes such a tape from a file, for the Monitor's R. Record catches the cassette output (C020h) while you SAVE or W, and gives it to you as a WAV file; the recording also stays in the deck to be played back. The language card puts 16K of RAM over the ROMs, as DOS 3.3 uses it for the other BASIC. The Disk II takes disk images (.dsk, .do, .po, .nib) in two drives; boot with PR#6 (or the Monitor's C600G), and Save writes the disk back as an image with what the program wrote to it. 50 Hz scanning is the Eurapple's: 312 lines a frame instead of 262. The ROMs are not included; your browser keeps them once loaded.

Memory chips live pins · click a pin for its fault menu

Every memory chip on the main board, from the RFI board's schematic: the 24 4116 dynamic RAMs in rows C (0000h–3FFFh), D (4000h–7FFFh) and E (8000h–BFFFh), one per data bit (the chip in column 3 holds bit 0 and the one in column 10 bit 7), the six 2316B ROMs D0–F8 and the text ROM at A5. A tile's dot lights while its chip is being accessed. Click a tile to see that chip's pins, which follow the bus on every clock. The RAMs are addressed twice in every cycle: by the video scanner while φ0 is low and by the 6502 while it is high, through the 74LS153 multiplexers (the 6502's address goes to RA0–RA6 as A7/A10, A2/A4, A0/A5, A8/A11, A3/A9, A1/A6 and A12/A13, row then column); the pins show the 6502's access.

To simulate a fault, click a pin for its menu. A pin on a line shared with other chips gets a tick box: without it, the buttons hold the whole line high or low, and every pin on that line, on every chip, sees the level; with it ("Disconnected from the line"), the fault is on this chip's pin alone. A pin with a line of its own has the plain choices: Disconnected (an input then floats high), High or Low. An address pin fault makes the chip use the wrong cell; a data pin fault changes that bit on reads and writes; a fault on RAS or CAS takes a RAM out of circuit (its bit reads 1); a ROM's chip select held high switches it off and INHIBIT' (CS2) held low switches all six off. A RAM fault shows in the picture too, because the video scanner reads the same chips. Faults are listed in the Debug pane and stay until cleared there, here, or by Master reset.

Every other ringed pin opens the fault menu: each of the 6502's pins is on a line of its own, because on the Apple II board the processor (H7/8) reaches the system bus through the 8T97 address buffers (H3–H5) and the 8T28 data transceivers (H10, H11). Program

Standard 6502 syntax, one instruction per line. Labels start in the first column or end with :; comments start with ;. Directives (dot optional): .org or * =, = or EQU, .byte, .word, .res, .end. Numbers: $1F, %1010, 42, 'A'; * is the current address; <label and >label give its low and high byte. Zero-page addressing is used automatically when the address is known to be below 0100h; write it with four digits ($0012) to force absolute. Code starts at the Load at address; an .org in the source overrides it. Import a file with the button or by dropping it on the editor.

Memory bitmap

Point at the bitmap to read a byte; click to show it in Memory.

Every bit of memory is one pixel. Each byte is a row of 8 pixels (bit 7 on the left) and each strip is one 256-byte page, read top to bottom. The background colour shows what each part of RAM is used for, read from BASIC's own pointers, so you can watch a program, its variables and its strings grow. The character ROM is shown too: every character is 8 bytes, so its shapes are visible. The red mark is the program counter and the blue mark the stack pointer.

    Starred cycles (rd*, wr*) are dummy accesses the 6502 makes while it works out an address or modifies memory; real hardware sees them, so they matter for I/O registers.

    Apple II hardware soft switches · keyboard · video scanner

    The Apple II has no interface chips: the 74LS138s at F12, F13, H12 and H2 decode C000h–C0FFh into strobes, and any access to an address acts, read or write. C000h reads the keyboard (bit 7 is the strobe flip-flop) and C010h clears the strobe; C020h toggles the cassette output and C030h the speaker; C050h–C05Fh set the eight soft switches in the 74LS259 at F14; C061h–C067h read the push buttons and the paddle timers on bit 7, and C070h starts the timers. The video scanner counts 65 states in a line (the first is the long cycle) and 262 lines in a frame; its address and the byte it drives out of RAM are what the 6502 reads at any address nothing answers (the floating bus).

    System memory map

    The defaults follow a common hobby layout: 16 KB RAM at 0000h, a 6522 VIA at 6000h and ROM from 8000h to FFFFh, which holds the NMI, reset and IRQ vectors at FFFA–FFFFh. The 6502 has no separate I/O space, so peripherals sit in the memory map.
