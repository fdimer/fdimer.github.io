Screen

Click the picture and type. Letters, digits and symbols go to the PET key with that character, whatever your keyboard layout; hold Shift with a letter for its graphics character. Enter is RETURN, Backspace is DEL, Esc is STOP, Home is HOME (Shift+Home clears the screen), Insert is INST, Tab is RVS, the arrow keys move the cursor, ^ is the up-arrow key and _ the left-arrow key. On the keyboard above, SHIFT stays down for the next key. Load ROM folder asks for the folder that holds your ROM files and fits the ones the chosen BASIC needs; the files must keep their standard names: basic-2-c000, basic-2-d000, edit-2-n and kernal-2 for BASIC 2; basic-4-b000, basic-4-c000, basic-4-d000, edit-4-n and kernal-4 for BASIC 4; characters-2 for both. The row of sockets shows which file sits in each ROM socket on the board. Click a socket to fit a ROM of your own there instead, whatever it is called: a different editor, a patched kernal, or an option ROM in the spare sockets UD3 and UD4. Load program puts a .prg file straight into memory: wait for READY, load it, then type RUN. The ROMs are not included; your browser keeps them once loaded.

Clicking φ0 pulses one clock, which is one bus cycle: the 6502 reads or writes memory on every cycle. /IRQ is level-sensitive and masked by the I flag; /NMI and /SO trigger on a falling edge. Holding RDY low stops the CPU on its next read cycle (writes still complete, as on the NMOS part). /RES low holds the CPU in reset; releasing it runs the 7-cycle reset sequence and loads PC from FFFCh.

Program

Standard 6502 syntax, one instruction per line. Labels start in the first column or end with :; comments start with ;. Directives (dot optional): .org or * =, = or EQU, .byte, .word, .res, .end. Numbers: $1F, %1010, 42, 'A'; * is the current address; <label and >label give its low and high byte. Zero-page addressing is used automatically when the address is known to be below 0100h; write it with four digits ($0012) to force absolute. Code starts at the Load at address; an .org in the source overrides it. Import a file with the button or by dropping it on the editor.

Hex bytes separated by spaces or newlines. Text after ; is ignored. Write FFFA: to continue loading at another address. Intel HEX files (lines starting with :) are also accepted and keep their own addresses. Raw binary ROM images (.bin, .rom) import here as hex. Memory

Scroll through all 64 KB. Click a byte to edit it (ROM too). Blue marks the instruction being executed, amber marks bytes written by the last instruction, underline marks the top of the stack. ROM is tinted; I/O registers show the value a read would return. With Follow PC ticked, each step brings the current instruction back into view; untick it to keep watching another area.

Memory bitmap

Point at the bitmap to read a byte; click to show it in Memory.

Every bit of memory is one pixel. Each byte is a row of 8 pixels (bit 7 on the left) and each strip is one 256-byte page, read top to bottom. The background colour shows what each part of RAM is used for, read from BASIC's own pointers, so you can watch a program, its variables and its strings grow. The character ROM is shown too: every character is 8 bytes, so its shapes are visible. The red mark is the program counter and the blue mark the stack pointer.

    Starred cycles (rd*, wr*) are dummy accesses the 6502 makes while it works out an address or modifies memory; real hardware sees them, so they matter for I/O registers.

    PET hardware PIAs · VIA · video

    PIA 1 (E810h) scans the keyboard: port A bits 0–3 pick a row, port B reads its eight keys. Its CB1 input is the VIDEO ON signal from the video counters; the falling edge at the end of each picture is the 60 Hz interrupt that runs the keyboard scan and the clock. PIA 2 (E820h) is the IEEE-488 data bus. The VIA (E840h) has the IEEE-488 control lines, the cassette lines, the user port, the character-set select on CA2 (POKE 59468,14 for lower case, 12 for graphics) and CB2, where sound comes out.

    System memory map

    The defaults follow a common hobby layout: 16 KB RAM at 0000h, a 6522 VIA at 6000h and ROM from 8000h to FFFFh, which holds the NMI, reset and IRQ vectors at FFFA–FFFFh. The 6502 has no separate I/O space, so peripherals sit in the memory map.
